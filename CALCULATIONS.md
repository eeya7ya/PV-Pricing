# eSpark Solar Calculator — Calculation Reference

This document traces **every formula actually executed by the code**, so the
numbers on screen can be audited line by line. It is generated by reading the
source, not from an idealized spec. Where the code makes a simplifying
assumption or carries an unverified constant, it is called out explicitly.

**Source-of-truth files**

| Area | File |
|------|------|
| Server billing pipeline (`/api/calculate`, `/api/calculate-npv`) | `server/routes.ts` |
| Tariff rates, pricing, add-ons, sizing, net-billing | `shared/jordanTariffs.ts` |
| PV yield physics (Quick Quote + Detailed) | `shared/jordanPVDesign.ts` |
| Electrical balance-of-system sizing | `shared/pvElectrical.ts` |
| Client tariff calculators (Buy-All-Sell-All path) | `client/src/lib/tariffEngine.ts` |
| Client state, PV-design override, BASS calc | `client/src/components/CalculatorLogic.tsx` |
| Results display formulas | `client/src/components/BeforeAfterResults.tsx` |

**Units & conventions**

- Energy in **kWh**; power in **kW** (AC) / **kWp** (DC).
- Tariff rates stored internally in **fils/kWh** (1 JD = 1000 fils). Helpers
  that return JD divide by 1000. The Industrial 4-period UI rates are stored
  in **¢/kWh** and divided by 100 (see `tariffEngine.ts`).
- A "month" is one of the 12 calendar months; the engine never sub-divides days.
- `efficiency` is a percentage (e.g. `95`); it is converted to a fraction
  (`/100`) before use.

## 1. Inputs

The calculator state (`CalculatorLogic.tsx`) holds:

- `customerType` ∈ {Residential, Commercial, Industrial, Hotels, Hospitals, Agriculture}
- `gridConnection` ∈ {Net billing, wheeling, Zero export, Buy all sell all, Legacy net metering}
- `consumption` = 12 monthly kWh values
- `efficiency` (%), `degradation` (%), `exportTariff` (JD/kWh), `tariffSupported` (bool)
- `sector` = `'auto'` or an explicit EMRC sector code
- Time-of-use factor grids (per month, 0–1):
  - Residential: `dayFactors`, `eveningFactors`, `nightFactors` (consumption split);
    `sunPeakFactors`, `sunMediumFactors`, `sunLowFactors` (PV generation split);
    `pvConsumeDay/Evening/Night` (self-consumption fraction).
  - Industrial: `period1..4Factors`, `sunPeriod1..4Factors`, `pvConsumePeriod1..4`.
- `pvDesign` (optional physics override), `electrical` (BoS design)

**Grid connection → Net-billing mechanism** (`CalculatorLogic.mechanismFor`):

```
wheeling            → M1_net_value_offsite
Zero export         → M3_zero_export
Buy all sell all    → M4_buy_all_sell_all
Legacy net metering → M5_legacy_net_metering
Net billing (else)  → M2_net_value_onsite
```

**Customer type → default EMRC sector** (`defaultSectorFor`), used when
`sector = 'auto'`:

```
Residential  → A1_subsidized (tariffSupported) | A2_unsubsidized
Industrial   → C2_medium_industrial (default) | C1/C3/C4 by size
Commercial   → B1_commercial
Hotels       → D1_hotel_post2008
Hospitals    → E1_private_hospital
Agriculture  → F1_agri_std
```

## 2. Main billing pipeline — `/api/calculate`

This is the path for every grid connection **except** "Buy all sell all"
(which is computed client-side, see §6).

### 2.1 PV generation target (X2)

```
total_annual_consumption = Σ consumption[month]               (12 months)
capFraction              = mechanismGenerationCapFraction(mechanism, sectorClass)
monthly_pv_generation    = (total_annual_consumption / 12) × capFraction
```

`capFraction` (`mechanismGenerationCapFraction`):

| Mechanism | Residential | Non-residential |
|-----------|-------------|-----------------|
| M1 wheeling | 0.50 | 0.50 |
| M2 net billing | **1.00** | **0.50** |
| M3 zero export | 1.00 | 1.00 |
| M4 buy-all/sell-all | 1.00 | 1.00 |
| M5 legacy | 1.00 | 1.00 |

So by default the modelled PV system generates, per month, a fraction of the
average monthly consumption. This is the "X2 = consumption/12 × cap" rule.

### 2.2 Inverter sizing and the residential cap

```
kWp_pre      = monthly_pv_generation / 150          (150 kWh/kWp/month = 1800/yr)
kWac_pre     = kWp_pre / DCAC_ratio                 (ratio 1.5 residential, 1.2 other)
estimated_kwac = kWac_pre / (efficiency/100)
inverter_kwac  = applyResidentialInverterCap(inverter_kwac_input ?? estimated_kwac,
                                             phase, sectorClass)
inverter_size  = inverter_kwac
kwp_dc         = inverter_kwac × DCAC_ratio
```

Residential inverter cap (`RESIDENTIAL_INVERTER_CAP_KWAC`): single-phase
**3.6 kWac**, three-phase **10 kWac**. Non-residential is uncapped.

**If the cap binds**, monthly generation is re-derived from the capped inverter:

```
monthly_pv_generation = kwp_dc × 150 × (efficiency/100)
```

### 2.3 Per-month PV generation vector

Precedence in `pvGenForMonth(monthIndex)`:

1. **PV-design override** (`monthly_pv_generation_override`, a 12-vector from the
   physics engine in §7) — used directly.
2. **Seasonal shares** (`detailedMonthly` on) — `annual_flat × share[m]`, where
   `share` is the region's monthly solar curve (`ZONE_MONTHLY_SHARES`).
3. **Flat fallback** — `monthly_pv_generation` every month.

### 2.4 Export rate

```
effective_export_rate_jd =
   export_tariff           , if export_tariff ≠ 0.04 (user override)
   netBillingExportRateJD  , otherwise  →  0.05 residential / 0.04 non-residential
```

### 2.5 Residential 3-bucket monthly calculation

For each month (`x1` = consumption, `x2` = PV generation):

```
Consumption split:   y1 = x1·dayFactor   y2 = x1·eveningFactor   y3 = x1·nightFactor
PV generation split: z1 = x2·sunPeak     z2 = x2·sunMedium       z3 = x2·sunLow
Self-consumption:    k1 = min(z1·pvConsumeDay,    y1)
                     k2 = min(z2·pvConsumeEvening, y2)
                     k3 = min(z3·pvConsumeNight,   y3)
self_consumption = k1 + k2 + k3
export  = max(0,z1−k1) + max(0,z2−k2) + max(0,z3−k3)
import  = max(0,y1−k1) + max(0,y2−k2) + max(0,y3−k3)
```

Bills:

```
bill_before_raw = priceMonthlyImport(total_cons = y1+y2+y3, before_tou)
import_cost     = priceMonthlyImport(import, imp_tou)        (0 if import = 0)
export_revenue  = 0                          if M3 zero-export or M5 legacy
                = export × effective_export_rate_jd  otherwise
raw_net_bill    = import_cost − export_revenue
```

`bill_before` and `bill_after` then pass through the credit ledger (§2.8) and
`finalizeBill` (§2.9).

For **TOU sectors only** (banks, telecom, hotels, hospitals, large industrial…),
the 3 residential buckets are mapped to EMRC's 3 TOU windows before pricing
(`mapResidentialBucketsToTOU`):

```
peak    = evening (y2)
partial = day·0.25 + night  (y1·0.25 + y3)
offPeak = day·0.75          (y1·0.75)
```
For tiered/flat residential sectors (A1/A2) the bucket split affects only
self-consumption/export, not the per-kWh rate.

### 2.6 Industrial 4-bucket monthly calculation

For each month, consumption splits into 4 periods (05–14, 14–17, 17–23, 23–05):

```
y1 = x1·period1   y2 = x1·period2   y3 = x1·period3   y4 = x1·period4
z1..z4 = x2 · sunPeriod1..4
k1..k4 = min(z_i · pvConsumePeriod_i , y_i)
self_consumption = Σ k_i
export = Σ max(0, z_i − k_i)
import = Σ max(0, y_i − k_i)
```

The 4 buckets map onto EMRC's 3 TOU windows for pricing:

- **M1 wheeling** (`mapFourBucketToWheelingTOU`): `offPeak = y1+y2`, `partial = y4`, `peak = y3`
- **All other mechanisms** (`mapFourBucketToStandardTOU`): `offPeak = y1`, `partial = y2+y4`, `peak = y3`

`bill_before_raw` and `import_cost` are priced via `priceMonthlyImport` on the
mapped TOU breakdown; export revenue and the ledger work exactly as in §2.5.

### 2.7 Import pricing — `priceImportJD`

Dispatches on the sector's `pricingModel`:

- **Temporary subscription** (if `isTemporary` and a `temporaryFils` exists):
  `monthlyKWh × temporaryFils / 1000`.
- **Tiered** (`priceTieredJD`): walk the tier ladder, charging each band's kWh
  at its `rateFils`, sum, ÷1000. (E.g. A1: ≤300 @50, 300–600 @100, >600 @200 fils.)
- **TOU-3** (`priceTOU3JD`): `(peak·peakFils + partial·partialFils + offPeak·offPeakFils)/1000`.
- **Flat / mixed-well** (`priceFlatJD`): `monthlyKWh × flatFils / 1000`.

All sector rates live in `SECTOR_TARIFFS` (full table in §10).

### 2.8 Net-billing credit ledger — `applyCreditLedger`

Run on `raw_net_bill = import_cost − export_revenue` each month, carrying a
`running_credit_balance` across months:

```
if raw_net_bill < 0:                 # exported more value than imported
    credit_generated = −raw_net_bill
    running_balance += credit_generated
    bill_after_credits = 0
elif running_balance > 0:            # draw down stored credit
    used = min(running_balance, raw_net_bill)
    running_balance −= used
    total_net_billing_savings += used
    bill_after_credits = raw_net_bill − used
else:
    bill_after_credits = raw_net_bill
```

### 2.9 Final bill assembly — `finalizeBill`

Applied to **both** the before-PV raw bill and the after-credit bill:

```
addOns      = calcUniversalAddOns(...)        # see §3
pfSurcharge = powerFactorSurchargeJD(...)      if sector allows PF penalty and pf < 0.88, else 0
subtotal    = max(0, rawBill) + addOns.totalJD + pfSurcharge
finalBill   = max(subtotal, minBill[sector])   # applyMinimumBillJD
```

Add-ons are charged on **imported** energy (so the before-PV bill uses total
consumption; the after bill uses the smaller import figure).

### 2.10 Annual adjustments

```
reset = applyAnnualReset(running_credit_balance, policy)   # default forfeit_year_end
total_cost_after += reset.forfeitedJD − reset.cashedOutJD

grid_fee_monthly = gridServiceFeeJD(...)        # §5
grid_fee_annual  = grid_fee_monthly × 12
total_cost_after += grid_fee_annual

annual_savings = total_cost_before − total_cost_after
```

Annual reset policies (`applyAnnualReset`):
- `forfeit_year_end` (default): surplus credit zeroed Dec 31, counted as a loss.
- `cash_out`: surplus refunded (reduces cost).
- `rollover_indefinite`: surplus carried to next year.

### 2.11 Outputs (`annual_summary`)

`pv_size` (monthly kWh), `inverter_size` (kWac), `annual_generation`,
`total_self_consumption`, `total_export`, `cost_before`, `cost_after`,
`annual_savings`, `export_revenue`, `efficiency` (fraction), `export_tariff`,
`net_billing_savings`, `final_credit_balance`, `grid_service_fee_jd_per_month/annual`,
`sector`, `kwp_dc`, `dc_ac_ratio`, `inverter_cap_*`, `mechanism_cap_fraction`,
`loses_residential_subsidy`, `eligibility_status`, `forfeited/cashed_out_credit_jd`,
`total_savings_with_net_billing = annual_savings + net_billing_savings`.

## 3. Universal add-ons — `calcUniversalAddOns`

All amounts in JD per month, summed into `totalJD`:

| Add-on | Formula | Default |
|--------|---------|---------|
| Rural electrification | `1 fils × importKWh / 1000` | on |
| Fuel clause | `fuelFils(month) × importKWh / 1000` | 0 fils for 2026-01…05 |
| TV fee | `1.0 JD` (residential sectors only) | on (residential) |
| Meter rent | 1-ph `0.2 JD`, 3-ph `0.5 JD` | on |
| GAM municipal | `≤200 kWh: 1.667`; else `1.667 + 0.005·(kWh−200)` | off |
| Waste fee | A `3.0`, B `2.0`, C `1.667` JD | none |

**Minimum bill** (`applyMinimumBillJD`): sector override if present (residential
A1/A2 = 1.75 JD), else residential 1.75 / non-residential 2.0 JD.

**Power-factor surcharge** (`powerFactorSurchargeJD`, NEPCO §I.1.d) — only for
sectors with `pfPenaltyApplies` (C2/C3/C4, F2, D1/D2-TOU):

```
if pf ≥ 0.88: 0
steps = round((0.88 − pf) / 0.01)
%/step = 0.77 (pf≥0.7) | 0.95 (≥0.6) | 1.2 (≥0.5) | 1.5 (else)
surcharge = billJD × (%/step × steps) / 100
```

## 6. Buy-All-Sell-All (client-side, `CalculatorLogic.tsx`)

Selected when `gridConnection = 'Buy all sell all'`. All generation is sold,
all consumption is bought (no self-consumption offset).

```
x2 (monthly generation) = total_annual_consumption / 12
```

**Residential** (`calculateBuyAllSellAll`): for each month —
```
importTariff  = tariffCalculator.calcImportCost(consumption)   # tiered/flat, §9
exportTariff  = x2 × exportRate
addOns        = calcUniversalAddOns(residential sector, consumption, …)
billBefore    = applyMinimumBillJD(importTariff + addOns, sector)
netCost       = billBefore − exportTariff
savings_month = billBefore − netCost  (= exportTariff)
```
`annual_savings = Σ billBefore − Σ netCost`.

**Industrial** (`calculateIndustrialBuyAllSellAll`): import priced by type —
- *Small Industrial*: `≤10 000 kWh → 0.06 JD/kWh`; surplus `> 10 000 → 0.068`.
- *Medium Industrial*: period split (off-peak/half-peak/peak/half-peak-night
  using the BASS factors) priced at `0.059 / 0.069 / 0.079 / 0.069 JD/kWh`.

Export = `x2 × export_rate` (default 0.05). The BASS time factors must sum to
1.000 (validated) and `inverter_size = inverterKWacFromMonthlyKWh(x2, class)`.

## 7. PV yield engine (`jordanPVDesign.ts`)

Active only when `pvDesign.enabled`; its monthly kWh vector then **overrides**
the consumption-based generation in §2.3, and its inverter kWac/kWp feed §2.2.

### 7.1 Tier 1 — Quick Quote (`quickQuoteYield`)

```
dcKWp  = sizeValue          (sizingMode 'kWp')
       = sizeValue / area_per_kWp[systemType]   (sizingMode 'roofArea')
PR     = prOverride ?? PR_DEFAULTS[systemType]   (res 0.78, com 0.80, ground 0.82, tracker 0.81)
annual = dcKWp × PVOUT_fix(region) × (PR / 0.80)
monthly[m] = annual × zoneShare[m]
specificYield = annual / dcKWp
```
`PVOUT_fix` per region is the Solargis level-1 yield (e.g. Amman 1820 kWh/kWp/yr);
the `/0.80` re-grosses out Solargis's embedded PR before re-applying the chosen PR.

Degradation curve: `year y → annual × (1−0.008) × (1−0.004)^y` (0.8 % LID + 0.4 %/yr).

### 7.2 Tier 2 — Detailed (`calculatePVYield`)

Full loss chain, month by month:

```
1. transposition = (GTI_opt/GHI) × (1 − 0.08·((tilt−tiltOpt)/60)² − 0.06·(azimuth/180)²)
   POA_annual = GHI × transposition
   POA[m]     = POA_annual × mountingUplift × zoneShare[m]   (uplift: fixed 1.0, HSAT 1.18, dual 1.30)
2. grossDC[m] = POA[m] × dcKWp
3. tempLoss[m]% = max(0, (T_cell − 25) × |tempCoeff|),  T_cell = T_amb[m] + (NOCT−20)·0.6
4. soilingLoss[m]% = baseSoiling × cleaningFactor × monthlyMult[m] / 12
5. constDcLoss% = mismatch + nearShade + horizonShade + interRowShade + spectrum
                + IAM + lowIrradiance + |tolerance| + dcWiring
6. monthlyDC[m] = grossDC[m] · (1−temp/100) · (1−soil/100) · (1−const/100) · (1+bifacialGain/100)
7. clip% = clippingLossPct(dcKWp/inverterKWac)
   monthlyAC[m] = monthlyDC[m] · ηeu · ηmppt · (1−clip) · invAvail
8. monthlyACFinal[m] = monthlyAC[m] · (1−acWiring) · (1−mvTransformer) · pvAvail · gridAvail
annual = Σ monthlyACFinal     PR = annual / Σ grossDC
```
Inverter clipping (`clippingLossPct`): 0 % at DC:AC ≤ 1.0, ramps to ~0.8 % at
1.2, ~1.5 % at 1.3, ~3.0 % at ≥1.5.

Degradation: `y=0 → annual·(1−LID/100)`; `y>0 → annual·(1−LID/100)·(1−deg/100)^y`.

## 8. Electrical balance-of-system (`pvElectrical.ts`)

### 8.1 String sizing (`sizeStrings`), with k = tempCoeffVoc/100

```
Voc_cold = Voc_stc · (1 + k·(Tmin − 25))         (Tmin default −5 °C)
Vmp_hot  = Vmp_stc · (1 + k·(Tmax − 25))         (Tmax default 70 °C)
maxByVdcMax = floor(Vdc_max / Voc_cold)
minByMppt   = ceil(mpptMin / Vmp_hot)
maxByMpptMax= floor(mpptMax / Vmp_hot)
modulesPerString = min(maxByVdcMax, maxByMpptMax)   (≥ minByMppt; longest valid string)
stringCount  = round(targetKWp·1000 / (modulesPerString · Wp))
stringsPerMppt = ceil(stringCount / mppts)
per-MPPT current = stringsPerMppt · Imp   (must be ≤ inverter max DC current/MPPT)
```

### 8.2 Cable sizing (ampacity + voltage drop), ρ = 0.0225 Ω·mm²/m

```
DC: designCurrent = 1.25 · Isc · stringsPerMppt;  pick smallest cable with ampacity ≥ designCurrent
    Vdrop = (Imp·stringsPerMppt) · (ρ·2·L / A);  upsize until Vdrop% ≤ limit (default 2 %)
AC: designCurrent = 1.25 · I_ac
    Vdrop = √3·I·(ρ·L/A) [3-ph]  or  2·I·(ρ·L/A) [1-ph];  limit default 1 %
```

### 8.3 Protection (`sizeProtection`)

```
String fuse required only if stringsPerMppt ≥ 3:
    In = min( nextStandard(1.5·Isc), module max series fuse )
DC disconnect = nextStandard(1.25 · Isc · stringsPerMppt)
AC breaker    = nextStandard(1.25 · I_ac)
```

### 8.4 AC current (`acCurrent`)

```
3-phase: I = (kWac·1000) / (√3 · Vac · pf)
1-phase: I = (kWac·1000) / (Vac · pf)
```
DC:AC warning raised above 1.55.

## 9. Client tariff calculators (`tariffEngine.ts`)

Used by the Buy-All-Sell-All residential path and the default presets.

- **Residential tiered** (preset `residential:tiered`): ≤300 @0.05, 300–600 @0.10,
  >600 @0.20 JD/kWh; export 0.04.
- **Residential flat** (`residential:flat`): ≤1000 @0.12, >1000 @0.15 JD/kWh.
- **Industrial TOU** (`industrial:tou`): per-period ¢/kWh ÷ 100; without a period
  breakdown it uses the 4-period average rate.

## 10. NPV / ROI endpoint — `/api/calculate-npv`

```
npv = −system_cost
for year = 1..project_life:                      (defaults: cost 5000, rate 0.05, life 25)
    degr   = (1 − 0.005)^year
    pv     = annual_savings · degr / (1 + discount_rate)^year
    npv   += pv
irr     = min( annual_savings / system_cost × 100 , 50 )
payback = system_cost / annual_savings
lcoe    = system_cost / (1000 · project_life)    (NOTE: annual_generation hardcoded 1000 — simplified)
```

## 11. Results display formulas (`BeforeAfterResults.tsx`)

```
roiPercentage          = annual_savings / cost_before × 100   (labelled "% lower bills")
selfConsumptionPercent = total_self_consumption / annual_generation × 100
Monthly Average        = cost_before/12  and  cost_after/12
Best Performance Month = month with max(savings)
Highest Bill Month     = month with max(bill_before)  (shows before → after)
Credits Generated      = Σ monthly_credit_generated
Credits Used           = Σ monthly_credit_used
```

KPI cards: **Annual Savings** = `annual_savings`; **System Size** =
`pv_size` kWh/month + `inverter_size` kW; **Self Consumption** =
`selfConsumptionPercent` + `total_self_consumption` kWh/yr; **Export Revenue**
= `export_revenue` + `total_export` kWh.

## 13. Known simplifications (verify before relying on absolute JD figures)

- Several TOU per-period rates (B3, D1/D2, E1) are **reconstructed around a
  confirmed flat anchor**, not published per-period values.
- Default PV generation (when the PV-design module is off) is a flat
  `consumption/12 × cap`, not a physics-based seasonal curve.
- `/api/calculate-npv` LCOE uses a hardcoded `annual_generation = 1000 kWh`.
- M3 grid fee reuses the M2 schedule (upper bound) until EMRC publishes M3 values.
- Fuel clause is 0 for all known 2026 months; future months default to 0.
